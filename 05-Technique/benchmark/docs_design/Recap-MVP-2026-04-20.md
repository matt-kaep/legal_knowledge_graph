# Récap journée — MVP benchmark CRFPA 2025

> Bilan autonome de la journée du 20 avril 2026 : du questionnement initial sur le format de benchmark jusqu'à la livraison d'un MVP de 38 questions consolidées sur 11 matières CRFPA.

---

## TL;DR

- **Design du benchmark figé** : rubrique hiérarchisée `core / expected / expert`, format JSON de sortie imposé, métriques composites.
- **Formats canoniques des sources figés** : articles/codes (slug + clé `code_civil:1240`) et JP (ECLI + `sens_vs_question` + `importance`).
- **Stratégie ground truth validée** : triangulation *sujet CNB + grille officielle CNB + meilleures copies IEJ* → aucune dépendance au LLM pour la connaissance substantielle.
- **MVP livré** : 38 questions consolidées sur 11 matières CRFPA 2025, 681 points de rubrique, 296 articles uniques, 188 JP.
- **Pipeline prêt à scaler** via subagents Opus en parallèle (1 par matière).

## Chronologie des décisions

### 1. Format d'évaluation

| Question posée | Décision |
|---|---|
| Format de la GT ? | Rubrique hiérarchisée, pas de réponse texte |
| Gestion de la difficulté ? | Proxies mesurables (`|rubric|`, `nb_sources`, `ratio_expert`), pas d'étiquette qualitative |
| Sortie LLM testé ? | JSON structuré imposé (points_cles, fondements, JP favorable/défavorable, sujets connexes) |

### 2. Formats canoniques des sources

Repris du pipeline existant `Hector AI/Tech/judilibre-api/enrichissement_base_complete.ipynb` (88 % de couverture sur 1.1 M décisions Judilibre) :
- Codes : slug ASCII lowercase (`code_civil`, `code_du_travail`)
- Articles : `{PREFIX}{NUMBER}` canonique (`1240`, `L122-14-3`)
- Clé de jointure : `code_civil:1240`
- JP : ECLI prioritaire + `sens_vs_question` + `importance` (1/2/3)

### 3. Stratégie de constitution

Évolution au fil de la journée :
1. *Initial* : 300 questions via extension Les-Audits-Affaires + doctrine + CRFPA
2. *Après brainstorming* : 300 questions via hybride CRFPA + doctrine, relecture par moi seul
3. *Pivot final* : **MVP 20-50 d'abord** pour valider le pipeline avant scaler
4. *Exploration terrain* : CRFPA officiel (CNB) + Cap'Barreau + IEJ Strasbourg suffisent largement — doctrine reportée Phase 2

## Découverte majeure — triangulation "clé en main"

Depuis la session 2025, suite à un recours administratif, le **CNB publie pour la première fois les grilles de notation officielles** des 12 épreuves CRFPA. Combiné aux meilleures copies IEJ, on a :

```
Sujet CNB         (question canonique)
  ✚
Grille CNB        (rubrique officielle — barème du jury national)
  ✚
Meilleures copies IEJ (articles + JP effectivement mobilisés par candidats admis)
  =
Ground truth validée par l'institution, sans annotation humaine dédiée
```

**Gain méthodologique** : le LLM n'a qu'à *formater* la connaissance externe dans notre schéma, il n'en est plus la source. Biais circulaire éliminé.

## Architecture du benchmark

### Format d'un cas (résumé)

```yaml
id: CNB-CIVIL-2025-Q1
branche: civil
question: "..."
perspective: demande | defense | neutre
rubric:
  core: [...]       # poids 3 — étudiant L2 doit citer
  expected: [...]   # poids 2 — attendu praticien
  expert: [...]     # poids 1 — navigation profonde KG
articles_attendus:
  obligatoires: ["code_civil:1240", ...]
  optionnels: [...]
jp_attendues:
  - ref: "ECLI:..."
    short_ref: "Cass. ..."
    sens_vs_question: favorable | defavorable | nuance | neutre
    importance: 1 | 2 | 3
pieges:
  not_to_cite_articles: ["code_civil:1382"]  # abrogé 2016
```

Chaque point de rubrique a un champ `sources` ∈ {`grille_cnb`, `copie_iej`, `llm_intrinsic`} pour tracer la provenance.

### Métriques associées

- `rubric_score = (3·cov_core + 2·cov_expected + 1·cov_expert) / total_weight`
- `recall_expert` : signal-clé pour différencier RAG vs GraphRAG
- `adverse_coverage` : JP défavorables effectivement citées
- `anti_hallucination` : sources abrogées / inventées
- Full spec dans [[Design-Rubrique-Hierarchisee]]

## Pipeline de production (validé)

```
1. Téléchargement   : curl + UA Mozilla → data/cnb-crfpa/
2. Lecture specs    : 3 fichiers Obsidian (formats canoniques)
3. Lecture sources  : grille (texte natif) + sujet + copies (scan)
4. Triangulation    : chaque point de rubrique taggé par provenance
5. JSON write       : rubrics/cnb-<matiere>-2025-consolidated.json
6. Rapport retour   : stats + écarts sources
```

### Industrialisation observée

- **10 subagents Opus en parallèle** (1 par matière) ont produit les JSON en ~15-20 minutes wall-clock total
- **Problème récurrent observé** : ~5/10 subagents terminent l'analyse mais s'arrêtent avant le `Write` final → relance nécessaire via `SendMessage` avec "ÉCRIS MAINTENANT" + contexte du transcript
- **Après relance**, tous ont écrit leur JSON sans refaire l'analyse (preuve que le transcript est conservé)

## Limites identifiées

### Technique

1. **100 % des 188 JP ont `uncertainty_note`** → le LLM connaît les principes (Chronopost, Ch. mixte 2013, Derguini/Lemaire...) mais pas les numéros de pourvoi / ECLI. **Passage Judilibre obligatoire** avant évaluation.
2. **Copies IEJ = scans manuscrits sans couche texte** → `pdftotext` retourne vide, `tesseract-fra` non installé. Les subagents les plus rigoureux ont rendu les PDF en PNG haute résolution + lecture visuelle. À industrialiser.
3. **Coquille dans la grille CNB elle-même** (ex : `Cass. com. 14 mai 2025 n° 27-17.948`, année impossible) → cross-check Judilibre même sur la source gold.

### Méthodologique

1. **Pipeline subagent peu fiable sur l'étape `Write`** : ~50 % de taux d'arrêt avant écriture sur le premier coup. Nécessite une stratégie de relance systématique ou une refonte du prompt pour forcer le Write en tout début de dernière phase.
2. **Contamination LLM** : les annales CRFPA 2025 sont probablement dans les corpus d'entraînement des modèles → risque de mémorisation pour les baselines. À mesurer en comparant 2024 vs 2025 (plus ancien vs plus récent).
