## Choix et décisions prises

### Ce qu'on acte

- les datasets benchmark officiels ne changent pas : `train_augmented_retrievable_strict` et `eval_rich_retrievable_strict` ;
- les scores déjà publiés restent les scores sur `G0` ;
- `G1` devient la base propre minimale de référence ;
- `G2` devient le meilleur candidat pour la prochaine vague de reruns graphe ;
- `G3` reste une variante plus agressive, utile pour comprendre jusqu'où on peut pousser le nettoyage.

### Ce qu'on ne peut pas encore conclure

On ne peut pas affirmer que le cleaning améliore réellement les résultats retrieval sans rerunner :
- cosine ;
- cross-modal ;
- PPR ;
- LightGCN.

Hypothèse de travail :
- `G1` devrait presque certainement battre `G0` à coût benchmark négligeable ;
- `G2` a de bonnes chances d'être le meilleur compromis scientifique ;
- `G3` peut mieux porter le sens du graphe, mais risque de perdre trop de couverture.

## Décision protocolaire supplémentaire — K-fold inter-graphes

Décision prise ensuite :

- le protocole benchmark officiel devient :
  - `5-fold CV` sur `train_augmented_retrievable_strict` ;
  - `eval_rich_retrievable_strict` gelé pour les scores finaux ;
  - même panel métrique ;
  - même règle de sélection des champions ;
  - même dénominateur GT de référence ;
  - couverture benchmark reportée explicitement pour chaque graphe.

La règle de sélection est désormais :

1. `Hit@10`
2. `NDCG@10`
3. `MRR@10`
4. `Recall@10`
5. `Normalized Rank`

`LLM Judge` reste une métrique finale d'analyse, pas une métrique primaire de sweep.

Le `negative mining` plus dur n'est pas abandonné ; il est simplement déplacé en **phase 2** du protocole.

But :

- mieux distinguer l'effet “meilleur graphe” de l'effet “meilleure stratégie d'entraînement”.
