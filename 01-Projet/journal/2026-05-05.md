# 2026-05-05 — Setup baseline B2 + bundle cluster

## Ce qui a été fait

### Décision : focus pénal pour itérer vite

Plutôt que de lancer la baseline B2 sur tout le corpus (1,07 M JP, ~20h sur Mac MPS), pivot vers un **subset pénal** :
- 118 112 JP pénales filtrées via citations d'articles pénaux (`code_penal`, `code_de_procedure_penale`, `code_de_la_route`, `code_de_la_justice_penale_des_mineurs`)
- Répartition : CC=97 060, CA=14 315, TJ=6 737
- 8 questions CRFPA pénales (3 droit pénal + 5 procédure pénale)

Permet une expérience qui tourne en ~10 min sur cluster L40S.

### Réorientation de l'XP : stratégies d'agrégation

Plus intéressant que de tester 5 modèles d'embedding × 3 K → tester **4 stratégies d'agrégation × 5 K** sur 1 modèle (e5-base) :

| Strategy | Logique |
|----------|---------|
| `union` | Article cité par ≥ 1 JP du top-K |
| `intersection` | Article cité par TOUTES les K JP |
| `majority` | Article cité par ≥ ⌈K/2⌉ JP |
| `weighted` | Top-N articles classés par Σ similarité des JP citantes |

→ 20 configs × 8 questions = 160 évaluations, **toutes comparables côte à côte** dans un seul CSV.

### Infrastructure produite

**Bundle autonome** (`05-Technique/benchmark/baseline_b2/penal_bundle.tar.gz`, 293 MB) :
- `jp_index_penal.parquet` (346 MB) — id, number, juris, text des 118k JP
- `graph_penal.npz` (2 MB) — sous-graphe CSR pénal
- `rubrics_penal.json` — 8 questions fusionnées
- `eval_rubric.py` — scorer CRFPA copié
- `run_cluster.py` — **script all-in-one** dans le pattern de `run_all_models.py` :
  - MODEL_REGISTRY, boucle séquentielle download → embed → eval → purge
  - Embedding resumable via `np.memmap` + state JSON
  - Auto-détection CUDA / MPS / CPU
  - 4 stratégies d'agrégation factorisées dans la classe `NaiveRetriever`

**Workflow cluster** :
```bash
scp penal_bundle.tar.gz cluster:~/
tar xzf penal_bundle.tar.gz && cd penal_bundle
pip install -r requirements.txt
export HF_TOKEN=... HF_HOME=/scratch/hf_cache
python run_cluster.py
```

### Découvertes en cours de route

1. **Pourvoi non unique** : 13k doublons intra-CC, formats hétérogènes CA/TJ, 16k collisions inter-juridictions. La clé fiable est `id` Judilibre. Le scoring CRFPA n'évalue de fait que les JP CC (regex format `XX-XX.XXX`).
2. **Champs metadata hétérogènes** : `summary` n'est dispo qu'à 95% en CC, **0% en CA/TJ**. `titlesAndSummaries` quasi vide partout. CA/TJ : seul `text` (médiane 10k chars). Justifie le chunking + mean pooling.
3. **OOM Mac MPS** : la première version de `embed_corpus.py` accumulait tous les chunks en RAM (~25 GB) → crash à 68%. Réécrit en streaming par batches de 4000 docs avec écriture incrémentale dans un memmap. Mais Mac MPS reste lent (~11 doc/s avec e5-small) → donc cluster L40S.
